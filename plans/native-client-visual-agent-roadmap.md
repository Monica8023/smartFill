# SmartFill 原生客户端与视觉执行迁移路线图

## 目标与边界

SmartFill 的产品入口从 Web 控制台迁移为桌面客户端和手机 App。页面理解只允许发生在截图驱动的视觉执行环中；页面字段扫描、页面别名、CSS/XPath、人工 DOM 字段映射不再属于产品能力。

浏览器仍可为当次截图生成短期目标 ID 和边界框，用于把模型决定安全地落地为点击或输入。它们是执行坐标，不是页面语义来源，不可跨观察复用，也不可保存为任务模板。

## 当前基线

- PR 1 的产品接口与控制台删除已完成：页面扫描、页面别名输入和人工 DOM 字段映射均不可再使用。
- 双模型真实视觉 POC 已完成，能够独立执行 ExpandTesting Notes 场景。
- PR 2 的通用生产链路已接通：默认运行装配使用视觉 Provider，目标驱动 Worker 支持登录/注册选择、
  菜单循环导航、可配置截图频率、缺失资料暂停和同会话续跑；Web 新任务强制提供业务目标。
- 人工登录会话池和同源心跳已接入：短信、邮箱、扫码或 SSO 首次由用户处理，进程存活期间可按
  会话键跨任务复用；跨客户端重启的加密 Profile 恢复留到桌面端系统密钥库阶段。
- 旧语义映射类目前仅供无视觉 Provider 的内部兼容测试使用，已不再进入配置了模型的生产执行路径。
  在桌面客户端封装前仍需完成物理删除，避免兼容代码长期留存。

## 架构决策

```text
手机 App（创建任务、查看进度、审批/接管）
              │ 加密 API + WebSocket
              ▼
       设备配对与任务中继服务
              │ 签名任务信封
              ▼
桌面客户端（任务/凭据保管 + 视觉代理 + 本机浏览器）
              │
              ├─ 截图 → 多模态模型 → 结构化决策
              └─ 策略门禁 → Playwright/CDP → 回读/再截图
```

- 桌面端是默认执行节点。首版采用 Tauri 2 承载现有 React 界面，Python/FastAPI/Playwright 通过打包 sidecar 运行；这样可复用当前代码并保留可见 Chrome/Edge 会话。
- 手机端是控制器，不直接执行任意网站自动化。iOS/Android 的浏览器沙箱、后台限制和 WebView 能力不足以稳定支持通用 Playwright/CDP；移动端通过已配对桌面端执行，后续可增加受控云浏览器作为可选执行节点。
- 手机端首版采用 React Native。它负责创建/复用任务、提供非敏感业务数据、查看实时截图和时间线、批准提交、提示桌面端处理 CAPTCHA/MFA。
- 密码和身份数据默认只保存在执行设备的系统密钥库：Windows Credential Manager、macOS Keychain、Android Keystore、iOS Keychain。中继服务只接触端到端加密任务信封和脱敏事件。
- 视觉模型接收截图、业务目标、允许动作和当次目标 ID；不接收 DOM 文本转储、页面字段扫描结果或密码明文。模型输出必须通过结构校验、Origin 白名单、动作风险策略和新鲜度校验。

## 分阶段实施

### PR 1：删除旧页面发现契约

范围：控制台、API、Browser Job 人工干预协议、文档。

- 删除 `/api/v1/browser/page-scan`、页面扫描请求/结果模型和 Worker `scan_page` 方法。
- 删除页面别名、入口/提交按钮别名配置，以及人工 DOM 字段候选选择。
- 保留业务字段 key、显示名、类型、敏感标记和来源字段。
- 旧任务快照中的 aliases 仅允许读取迁移，不再参与新任务执行或在 UI 中展示。

验收：旧接口返回 404；新控制台和 API 不产生 selector/field mapping；历史任务仍能复用业务数据。

### PR 2：把 POC 提升为通用视觉执行器

范围：`vision.py`、`vision_poc.py` 拆分出的 production agent、Browser Worker 装配。

- 将 Notes 专用目标改为通用 `TaskGoal + WorkflowStep + OutcomePredicate`。
- 每轮严格执行 Observe → Decide → Policy → Act → Verify；导航、弹窗、滚动和提交后必须重新截图。
- 删除 `SemanticFieldMapper`、Accessibility Tree 语义评分和基于 alias 的入口/提交选择；DOM 只保留短期目标 ID、可见性、可操作性和输入回读。
- Flash 作为默认感知模型；低置信度、连续无进展或结果冲突时升级 Plus；仍不确定则进入 `visual_review`。
- 服务启动时缺少模型凭据应显示“视觉执行未配置”，不得静默回退 DOM 模式。

验收：ExpandTesting Notes 双模型真实场景通过既定门槛；代码库不存在旧语义映射执行路径；模型不可引用旧观察或任意 selector。

### PR 3：桌面客户端 MVP

范围：`apps/desktop`、sidecar 打包、自动更新。

- Tauri 提供任务列表、复用、运行监控、浏览器打开/关闭、诊断包导出和模型设置。
- sidecar 只监听 loopback，启动时生成会话令牌，父进程退出时回收服务；浏览器窗口默认可见并由用户手动关闭。
- 支持本机受支持浏览器、应用数据目录、系统密钥库和崩溃恢复。
- Windows 先行，随后补 macOS；Web 控制台降级为开发/诊断壳，不作为最终产品入口。

验收：干净 Windows 机器单安装包可运行，无需 Python/Node；升级不丢任务模板；卸载可选择保留或删除本地数据。

### PR 4：设备配对与同步服务

范围：账户、设备、任务信封、事件流。

- 桌面端生成一次性 QR 配对码；手机端完成设备公钥交换。
- 命令具备签名、过期时间、幂等键和撤销能力；事件通过 WebSocket 推送，断线后按序补齐。
- 中继端保存最小元数据，截图短期存储并可禁用；敏感值保持端到端加密。
- 任务所有权、Origin 白名单变更和提交批准均进入不可变审计事件。

验收：重放/伪造/过期命令被拒绝；桌面离线时任务保持待执行；解除配对后旧设备无法下发命令。

### PR 5：手机 App MVP

范围：`apps/mobile`，Android/iOS。

- 展示设备在线状态、任务模板、复用回填、实时截图、步骤进度和诊断摘要。
- 支持提交审批、暂停/取消、提醒用户到桌面处理 CAPTCHA/MFA。
- 手机端可采集业务数据，但敏感值只有在明确选择同步时才用桌面设备公钥加密传输。
- 不嵌入通用自动化 WebView，不承诺手机后台持续执行浏览器任务。

验收：同一任务可从手机创建、由桌面执行、在手机批准并看到最终结果；锁屏/断网恢复不产生重复提交。

### PR 6：评测、灰度与退役 Web 产品入口

- 扩展评测集：登录/注册、模态表单、iframe、Canvas、动态列表、反爬站点、不同语言、缩放和暗色模式。
- 指标：端到端完成率、`pass@1/pass@3`、错误点击、错误字段写入、假完成、人工接管率、模型成本和 p95 延迟。
- 灰度顺序：内部 Windows → 受邀桌面用户 → Android/iOS 控制器 → 可选云执行器。
- 达到安全与成功率门槛后，移除 Web 产品路由，只保留本地诊断页面和 API 文档。

## 关键依赖与风险

- PR 3 依赖 PR 2 的通用视觉执行接口稳定；PR 5 依赖 PR 4；评测框架贯穿所有阶段。
- 最大技术风险不是截图识别本身，而是目标落地稳定性、页面状态变化、成本/延迟和成功结果验证。
- 反爬网站对可见本机浏览器通常比数据中心无头浏览器友好，但不能保证绕过站点风控；产品必须把挑战识别为人工接管，而不是尝试规避。
- Tauri + Python sidecar 可最快复用现有资产，但增加安装包和进程生命周期复杂度。视觉执行核心稳定后，可再评估 Rust/Node 单进程重写，不应作为 MVP 前置条件。

## 回滚与兼容

- 每个阶段由能力开关隔离；回滚只能回到上一版视觉执行器，不能恢复 DOM 页面理解。
- 历史模板迁移时丢弃页面 aliases 和人工映射，只保留业务字段、值策略、URL、步骤顺序和提交策略。
- 数据迁移必须可重复执行；客户端升级前自动备份本地数据库，并保留一版可读兼容窗口。

## 自审结论

最容易被低估的两点是：手机端不能被当作桌面浏览器 Worker 的等价替代，以及“完全视觉”仍需要非语义的动作落地通道。若连短期目标 ID、可见性和回读都禁止，模型只能依赖裸坐标，可靠性和安全性都会明显下降。因此边界应定义为“视觉模型独占页面理解，确定性执行器独占动作落地和验证”，而不是“模型直接控制一切”。
